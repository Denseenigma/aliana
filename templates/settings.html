Auto-scan

Runs a network scan on a schedule, using the profile selected on the dashboard (now {{ settings.profile_label }}). Automatic scans join the same queue as everything else. The first one runs a minute after switching on; after that the interval counts from the end of the last network scan.

Device identification

After each scan Aliana works out what each device is and what it's called, using light, read-only lookups that devices on a LAN answer all the time: NetBIOS names (Windows), mDNS / Bonjour (Apple, Android, printers, Chromecast, smart-home), UPnP descriptions (TVs, routers, speakers), reverse DNS against your router, and the title / certificate of web interfaces already found open. Excluded hosts and never-probe ports are skipped. The MAC vendor database is always used.

Downloads the latest IEEE registry (needs internet on the Pi).

Never-probe ports

Ports that are still reported as open but never get service-identification probes. Use this for devices that accept a connection and then go silent (e.g. door-access controllers on 9999), which otherwise stall the "Identifying services" stage and can upset small embedded devices. Takes effect from the next scan.

Default: . Comma-separate to add several at once.

Exclusions

Addresses Aliana never scans — not even a ping. Network scans skip them (nmap --exclude) and Deep scans of them are refused. Enter one IP, a range (172.16.0.10-20 or 172.16.0.10-172.16.0.20) or a block (172.16.5.0/24), with an optional note. Host cards also have an Exclude button.

Subnet size guard

Protects against accidentally scanning a huge network. Applies to every scan — dashboard, Pi screen, Queue page and auto-scan.

RMM integration

Checks whether scanned devices are managed by your RMM: Aliana pulls the RMM's device list (read-only) and matches hosts by MAC address, then by hostname. Computers that aren't in the RMM get a No RMM agent finding. Printers, cameras, door controllers and network gear show "no agent expected".

Credentials are stored on this Aliana unit and never shown again in the browser. Use a dedicated API user with view-only permissions. The Pi needs internet access to reach the RMM's API.
